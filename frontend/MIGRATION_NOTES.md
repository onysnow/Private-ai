## Remaining hand-rolled markup (follow-up punch list)

- The `<section className="card">` panel-by-panel conversion is done -- every panel in `app/page.tsx` now renders through `Card`/`CardHeader`/`CardTitle`/`CardContent` (with `CardDescription` where the panel had an intro paragraph).
- Eleven `<select>`s are now migrated to `Select`/`SelectTrigger`/`SelectValue`/`SelectContent`/`SelectItem`: the connector-credentials provider picker (backup & restore panel, 2026-09-27), the source-type picker in the source & exact evidence capture panel (2026-09-27, static 6-option list), the investigation-timeline panel's precision and status pickers (2026-09-27, static 5-option lists each: `day`/`month`/`year`/`range`/`unknown`; `asserted`/`verified`/`approximate`/`disputed`/`unresolved`), the document-ingestion panel's extraction-relationship source/target entity pickers (2026-09-27, dynamic `entities.map()` lists with a placeholder in place of the old empty-value `<option>` -- Radix `Select` doesn't accept `""` as a real item value, so the placeholder now comes from `SelectValue`'s `placeholder` prop instead of a literal first `<option value="">`, same displayed behavior), the external-connectors panel's provider picker (2026-09-27, dynamic `providers.map()` list, no placeholder needed since it has no empty-value option to begin with), the external-connectors panel's `entityId` picker in the "Enrich a canonical entity" sub-panel (2026-09-27, dynamic `entities.map()` list, same placeholder workaround as the extraction-relationship pair), the external-connectors panel's `inv` investigation picker (2026-09-27, dynamic `invs.map()` list, no placeholder needed since `loadAppBootstrap()` auto-selects the first investigation on load), and the relationship-graph panel's `relSource`/`relTarget` pickers (2026-09-27, dynamic `entities.map()` lists, no placeholder since `loadEntities()` auto-fills both -- converted together in one commit). The credential-provider picker's conversion was the first real usage of `components/ui/select.tsx` anywhere in the app, and it has a real cost worth knowing before converting more: first-load JS for `/` jumped from 173 kB to 207 kB (+34 kB), because `@radix-ui/react-select` (plus its focus/positioning machinery) was previously fully tree-shaken out and now isn't. This is a one-time cost, not a per-select cost -- confirmed by every conversion since, none of which moved the bundle size at all (still 207 kB after nine more conversions). All eleven selects were chosen specifically because they have zero test coverage (`grep`ed `tests/` for each state-variable name plus distinguishing placeholder/option text, and cross-checked against every `selectOptions(...)` call site in `tests/` directly), so no interaction-test rewrite was needed for any of them.

**The untested-`<select>` candidate list is now exhausted.** Every native `<select>` remaining in `app/page.tsx` is exercised via `user.selectOptions(...)` in `tests/` (confirmed: `leadPriority`, `relSchema`, the relationship-evidence-attach select, `claimStatus`, the reasoning-module select) -- converting any of those will require rewriting that test's interaction to Radix's click-trigger-then-click-item pattern, on top of the `onChange`→`onValueChange` code change. Worth noting for `relSchema` specifically: `tests/test-page-relationship-graph.test.tsx` finds it via `getAllByRole('combobox').find(el => (el as HTMLSelectElement).value === 'Ownership')` rather than by label -- this filter depends on the element having a native `.value` property, so it kept resolving correctly once `relSource`/`relTarget` (siblings in the same form) became Radix trigger buttons, since those don't have a `.value` property and get filtered out. If `relSchema` itself is ever converted, that test line will need rewriting regardless. No `Checkbox` component exists at all yet; adding one is a separate PR. No `Slider` component exists either, so the one `<input type="range">` in the app (claim confidence) also stays native.
- Most action controls still use native `<button>`, `<input>`, `<textarea>`, and `<select>`
- Dialog-like and menu-like interactions are still custom and can migrate to `Dialog` / `DropdownMenu`
- Claim/evidence and relationship workspaces still render custom list/row layouts that can migrate to `Table`, `Tabs`, and additional `Card` composition

## Follow-up strategy

1. Convert one workflow section per PR to keep risk and review size low.
2. Replace native controls in each section with matching shadcn primitives while preserving existing handlers/state.
3. Keep visual/structural-only scope (no behavior changes) and validate with `npm run typecheck` and `npm run build` each step.

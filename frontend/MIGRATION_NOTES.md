Two real jsdom/testing-library gaps surfaced along the way:
  1. **Radix `Select.Trigger` (`role="combobox"`) has no accessible name from its visible text.** `combobox` is not a name-from-content ARIA role -- its accessible name comes only from an associated `<label>`, `aria-label`, or `aria-labelledby`, none of which the trigger has. `screen.getByRole('combobox', {name: 'normal'})` never matches even though the trigger's text is literally "normal" (confirmed by logging `dom-accessibility-api`'s `computeAccessibleName()` against every combobox on the page -- every Radix `Select` trigger came back with an empty accessible name, while the native `<select>`s that have an `aria-label` do get one). Fixed the same way `relSchema`'s pre-existing test already worked around a related problem: `screen.getAllByRole('combobox').find(el => el.textContent === 'normal')`, a content-based lookup rather than a name-based one.
  2. **Radix `Select`'s open/select interaction needs Pointer Events capture methods and `scrollIntoView`, none of which jsdom implements.** Clicking the trigger threw `target.hasPointerCapture is not a function`. Added minimal no-op polyfills for `hasPointerCapture`/`setPointerCapture`/`releasePointerCapture`/`scrollIntoView` to `test-setup.ts`, guarded on `typeof Element !== 'undefined'` since some test files in this suite run under Vitest's `'node'` environment (no DOM globals at all) and would otherwise throw on load.

## Values the app needs that the suite does not define

- **Red Flag level · strong** — No graded red-flag strength exists in the suite (only Standard §10.2 'Red flags versus conclusions'). The suite would need a strength scale that still stops short of a finding.
- **Red Flag level · textbook** — The suite has no 'meets the published definition' level and leans against one (§10.2: patterns do not establish fraud). It would need a rule that meeting a published indicator definition is still an indicator, not a finding.
- **To check answer · shows** — The suite has no record for a person's answer to whether a passage shows an indicator (Module 06 rule 1's evidence buckets are for hypotheses). It would need an indicator-check record.
- **To check answer · does_not** — As for 'shows': no indicator-check record.
- **To check answer · unclear** — As for 'shows': no indicator-check record.
- **Missing value answer · not_needed** — The suite's null rules do not separate not-applicable from unknown; it would need a not-applicable marker.
- **Claim confidence · number 0..1** — The suite forbids a bare number in place of a likelihood term (CALIBRATED_CONFIDENCE_LANGUAGE Rule 1); a claim carries confidence_term, confidence LOW|MEDIUM|HIGH and confidence_basis.
- **Lead priority · urgent** — No level above high; time sensitivity is a prioritisation factor (TAS Module 07 rule 2), not a level.
